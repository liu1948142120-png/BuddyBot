## 一、接入前检查清单

接入任何客户端之前，先确认这三件事，**缺一个都接不上**：

| # | 检查项        | 在哪看       | 正常状态                      |
| - | ---------- | --------- | ------------------------- |
| 1 | 账号池有在线账号   | 「账号」页     | 至少 1 个账号状态为「在线」           |
| 2 | 网关已启动      | 「仪表盘」顶部状态 | 显示运行中、监听 `127.0.0.1:7863` |
| 3 | 有网关 API 密钥 | 「API 密钥」页 | 有一个根密钥（首次启动自动生成）          |

> 网关没启动：仪表盘点「启动」；账号全不在线：先去账号页登录或导入凭证。

## 二、方式一：智能体接入页一键接入（推荐）

「**智能体**」页内置了主流客户端的自动接入，**选中客户端 → 勾选要用的模型 → 一键写入**，软件会自动改写对应客户端的配置文件，无需手动编辑。

支持的客户端（共 14 个）：

| 客户端                   | 一键接入做的事                                                                   |
| --------------------- | ------------------------------------------------------------------------- |
| Claude Code           | 写入 `~/.claude/settings.json` 的 `ANTHROPIC_BASE_URL` / `AUTH_TOKEN` / 模型槽位 |
| Codex                 | 写入 `~/.codex/config.toml` 与 `auth.json` 的 `OPENAI_API_KEY`                |
| OpenCode              | 写入 `~/.config/opencode/opencode.json` 的 provider                          |
| Pi CLI / PI-Desktop   | 写入 `~/.pi/agent/models.json`（PI-Desktop 写入后需在其设置→导入→模型里手动导入一次）            |
| Kimi Code             | 写入 `~/.kimi-code/config.toml`                                             |
| CodeBuddy / WorkBuddy | 写入各自 `models.json` 的自定义模型条目（原有模型不动）                                       |
| ZCode                 | 写入 `~/.zcode/v2/config.json`（**需先退出 ZCode**，运行中会被其退出时覆盖）                  |
| Qwen Code             | 写入 `~/.qwen/settings.json` 与环境变量密钥                                        |
| MiniMax Agent         | 写入 `~/.minimax/config.yaml`                                               |
| Crush                 | 写入 `~/.config/crush/crush.json`                                           |
| Aider                 | 写入 `~/.aider.conf.yml`                                                    |
| Zed                   | 写入 `settings.json`；密钥进系统凭据存储（钥匙串/凭据管理器）                                   |
| Continue              | 在 `~/.continue/config.yaml` 的 models 列表追加网关条目                             |

**两个实用功能：**

- **自动备份**：每次写入前自动备份原配置；
- **一键恢复**：接入出问题时，「智能体」页 → 该客户端 → 恢复备份，配置原样还原，不用担心改坏。

**操作步骤（以 Claude Code 为例）：**

1. 「智能体」页 → 找到 Claude Code；
2. 勾选要暴露给它的模型（默认选前 3 个可用的）；
3. 点「接入」→ 提示成功；
4. **重启该客户端**（多数客户端启动时才读配置），即可用账号池的模型对话。

## 三、方式二：手动填网关参数

任何支持「自定义 OpenAI 兼容接口」的客户端（ChatBox、Cherry Studio、沉浸式翻译、Dify 等）都能接，填这四项：

| 参数                | 值                                      |
| ----------------- | -------------------------------------- |
| API 地址 (Base URL) | `http://127.0.0.1:7863/v1`             |
| API Key           | 「API 密钥」页复制的根密钥（`sk-` 开头那串）            |
| 模型列表接口            | `GET /v1/models`（客户端支持"获取模型"按钮会自动拉取）   |
| 对话接口              | `POST /v1/chat/completions`（OpenAI 格式） |

**连通性自测**（浏览器或终端）：

```bash
# 通了会返回模型列表 JSON
curl http://127.0.0.1:7863/v1/models -H "Authorization: Bearer sk-你的密钥"
```

**注意事项：**

- 网关默认**只监听本机**（127.0.0.1）。别的设备要访问：设置 → 网关服务里改监听地址，并配合 IP 白名单收紧访问；
- 模型名以 `/v1/models` 返回的为准，账号池里有什么模型就填什么；
- 修改端口/密钥后，已接入的客户端要同步改。

## 四、接入失败排查表

按报错现象对号入座：

| 现象                            | 原因                       | 解决                          |
| ----------------------------- | ------------------------ | --------------------------- |
| 客户端报 **401 / Unauthorized**   | API Key 不对               | 重新从「API 密钥」页复制；确认没混入空格      |
| **连接拒绝 / Connection refused** | 网关没启动，或客户端在别的设备上访问       | 仪表盘启动网关；跨设备需改监听地址 + 白名单     |
| 模型列表是**空的**                   | 账号池没有在线账号                | 账号页把至少一个账号恢复在线（重新授权或刷新余额）   |
| 报 **429 / 频繁**                | 所有在线账号都在冷却               | 多加几个账号分流；或调低账号池并发           |
| 报 **403**                     | 触发 IP 黑白名单               | 设置 → 安全与访问，检查名单             |
| 时通时断                          | 某账号 Token 失效被熔断，账号池只剩一个号 | 账号页看哪个号「需重新登录」，恢复它          |
| 一键接入后客户端没变化                   | 客户端启动时才读配置               | 重启该客户端；PI-Desktop 需手动导入一次模型 |

**万能定位法**：「日志」页看请求记录——客户端的请求有没有打到网关、返回码是多少，一眼定位是"没进来"（客户端配置问题）还是"进来了但被拒"（密钥/白名单/账号问题）。

## 五、附录：JSON 导入凭证失败排查

「账号 → 导入凭证」按报错对号：

| 报错                                | 含义                       | 解决                                           |
| --------------------------------- | ------------------------ | -------------------------------------------- |
| `凭证缺少 accessToken / refreshToken` | JSON 里没有可用 token         | 补上 `accessToken` 或 `refreshToken` 字段（至少一个非空） |
| `token 为官方客户端加密信封`                | 这份 JSON 是官方客户端加密形态，读不出明文 | 该账号需在官方客户端内登录使用，或改用 OAuth 扫码登录               |
| `该文件为加密导出，请输入导出密码`                | 导出时设了密码                  | 输入当初导出时设置的密码                                 |
| `凭证缺少 uid`                        | JSON 里没有 uid 字段          | 能导但建议补上，避免同账号重复成两条                           |
| `凭证格式无效`                          | 内容不是合法 JSON              | 检查是否复制完整、有无多余字符                              |

**最小可用模板**（只需 token 字段非空即可导入）：

```json
{
  "uid": "账号的uid",
  "nickname": "显示昵称",
  "accessToken": "eyJ...",
  "refreshToken": "eyJ...",
  "realm": "cn"
}
```

`realm` 填 `"cn"`（国内版）或 `"global"`（国际版）；不填则按 `domain` 自动判断。
